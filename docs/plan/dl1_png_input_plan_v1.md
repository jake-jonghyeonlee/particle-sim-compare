## 4. Contract choices and recommended design

### 4.1 Adapter boundary and missing metadata

| Alternative | Benefits / cost | Decision |
|---|---|---|
| Export existing strict v1 manifest and NPY assets; separate versioned import report | Reuses all validators, train/search, checkpoint configuration and path safety; requires explicit lineage/design/grid before model-ready export | **Recommend for v1.** Automatic generation means the program writes the manifest, not that it invents missing metadata. |
| Extend manifest to accept PNG plus stack/provenance/new extent fields | Requires new schema version, dual-version loader and checkpoint policy; mixes source decoding with tensor loading | Defer; only revisit through a reviewed v2 plan if actual limitations require it. |
| Relax v1 to accept null metadata/grid or unknown extra fields | Makes incomplete imports look trainable, weakens existing strictness and provenance | Reject. |

Proposed CLI is `python -m psdl1.import_png --root ROOT --out OUTPUT`, defaulting to inspection. It always attempts a versioned report and preview for valid models, without requiring lineage/grid. Add `--export --metadata METADATA_JSON --candidate-grid G` to generate `OUTPUT/manifest.json` and contained `assets/*.npy` automatically. CLI spelling is a proposal to freeze at T1 acceptance, not an existing command.

Metadata JSON has a versioned strict schema (e.g. `dl1_png_metadata_v1`) and exact `models` mapping from source model names to user-provided `lineage_id` and `design_version`; no labels, split, hotspot, default grid, or inferred IDs. Reject duplicate keys, unknown/missing models and invalid strings. Partial metadata is permitted in inspection and listed as pending; export requires every discovered model to be valid and mapped. Missing export metadata/grid produces a diagnostic report and nonzero result **without publishing a model-ready manifest**. This intentional prerequisite must be visible in CLI help and docs, not discovered only after a loader failure. A future demand for trainable manifests without that metadata requires explicit contract replanning.

Use output outside the input tree; never modify original PNGs. Export all requested models or none: invalid files must not silently disappear from the training pool. Unresolved relations are not invalid images and may be represented as partial/unavailable while preserving global CNT geometry. New output bundle only; refuse an existing destination rather than replacing user files. Build in a sibling staging directory, validate assets and manifest there, then publish the directory atomically. A failed/blocked import may publish a clearly diagnostic-only report/preview bundle, never a stale or partial `manifest.json`. Reruns use a new output destination. Interruption leaves identifiable staging output for explicit inspection, not automatic deletion.

### 4.2 Frame, IDs, status, and sidecar

Keep `SCHEMA_VERSION`, `MODEL_INPUT_VERSION`, NPY encoding, endpoint feature dimension, and model weights format unchanged. `unit_size_um=[W*0.1,H*0.1]` is a compatibility field for full input extent; document that it does **not** assert a single physical unit. Sidecar explicitly records `comparison_scope: full_frame`, `frame_extent_um`, `core_bbox_xyxy_px:[500,500,W-500,H-500]`, `core_layout:[2,2]`, `single_unit_extent_um:null`, original `shape_yx`, pitch 0.1, local edge origin `[0,0]`, and model-wide stack table. Reject W≤1000 or H≤1000 under this source contract. No bbox drives input transforms.

For size semantics, the alternative is a v2 rename from `unit_size_um` to `frame_extent_um` plus an optional separately supplied physical-unit field; that is clearer naming but entails loader/model-fingerprint migration and explicit rejection or conversion of older checkpoints. Recommend the documented v1 compatibility alias plus sidecar for this feature because the current validator already enforces full extent. Never put a guessed single-unit or core size into the old field. Likewise, adding stack/provenance directly to `Element`/`Product` is a possible explicit v2 contract revision, not an allowed unknown-field extension to v1.

Product ID is the unchanged model folder name; electrode ID and default role are unchanged electrode folder names; actual layer is the full suffix after the first separator. Preserve stack separately in the sidecar. Same sequence with different layer names anywhere in a model is an error; duplicate electrode×layer assets are errors even if names differ in zero padding/separator. Repeated actual-layer names at different stack positions must be reported; if they collide with a v1 binding, block export rather than merging or renaming layers. Do not case-fold or trim source names into accidental aliases: reject invalid identifiers with path diagnostics.

Element/frame/component/connection IDs are derived from canonical source tuples and binary geometry, never directory enumeration, absolute root path, or Python hash. Specify canonical JSON plus SHA-256 for filename-safe IDs; collision check emitted IDs. Component identity includes model, numeric CNT stack, exact CNT layer, source asset binding and its original-coordinate component pixels. Preserve original filename/relative path separately; equivalent separator/zero-padding spellings must normalize the binding consistently. File-byte hashes and canonical binary-mask hashes serve different provenance roles. A renamed/re-encoded file can change source inventory hashes without changing logical relationships.

`import-report.json` uses explicit `report_schema_version: dl1_png_import_v1`, metadata schema, algorithm ID/version, component neighbourhood and pending policy. Include per-file path, byte hash, decoded mode/shape, binary mask hash/polarity; model IDs/stack table; geometry/valid assumption; each component's bounds/pixel count/hash, full above/below overlap candidates, selected candidates, ignored lower candidates with reason, skipped modeled upper layers, common-intersection evidence, both endpoint references and pixel/µm coordinates; unresolved reasons; errors/warnings; metadata/grid readiness; extraction/export status; generated manifest hash, asset hashes and Product input identities when exported. Reject unsupported report versions when reading a report for preview/verification. Stable payload/order should reproduce; omit timestamps or keep them outside identity-bearing content.

Store `electrical_verification: not_performed` and `real_data_validation: not_performed` prominently. `observation: observed` on a generated relation means its source masks are observed, never electrically verified. When at least one component is resolved and others unresolved use `connectivity_observation: partial`; zero resolved means `unavailable`, including no/empty CNT source. If all nonempty components resolve under the recorded rule, `complete` can describe **extraction coverage only**, with sidecar explicitly saying so and `electrical_verification` unchanged. Missing `cno` and present-but-empty/white-only CNT are distinct report reasons; neither establishes verified absence. Global `cnt` is the union of **all** decoded CNT foreground, including unresolved components. Do not fill missing endpoint objects to make an unresolved relation fit v1.

The sidecar is outside the strict model manifest and is delivered with the export bundle. Export validation binds it to manifest/assets by hashes and a `--verify-bundle` importer mode checks those links without source PNGs or network. Legacy NPY manifests can still load without a sidecar; no claim is made that arbitrary consumers retain provenance after users detach the report. Train/checkpoint input identities describe model input, not the entire original PNG inventory. Do not inject report fields into model features.

### 4.3 Strict source decoding

Use Pillow, lazily imported by the PNG adapter so legacy NPY use remains independent. Declare a PNG optional dependency in `pyproject.toml` using the already-tested locked Pillow version/range; no lock refresh/download is necessary. Reuse NumPy and standard library for component labeling, not an undeclared SciPy/OpenCV dependency.

Support single-frame PNG modes `1`, `L`, `RGB`, `LA`, `RGBA`, and palette `P` only when decoded pixels are exactly black/white and every alpha value is fully opaque. Validate RGB channels, palettes and transparency after exact decoding, with no luminance conversion, colour/gamma adjustment, EXIF transpose, or threshold. Reject intermediate grey, coloured pixels, transparent/semitransparent pixels (including alpha=0), unsupported bit-depth/modes, corrupt/truncated files, multi-frame PNG, or nonidentity orientation metadata with individual paths/reasons. Fixture-confirm the actual Pillow mode behavior; no blanket “all PNGs supported” claim. Do not disable decoder resource limits silently; report limits as import errors and leave real-size policy pending.

All files named `.png` at the expected depth are checked; malformed names, duplicate normalized bindings, conflicting stacks, shape mismatches, unsupported layouts and escaping source symlinks are errors. Ignore unrelated non-PNG files only with an inventory warning. Source root relocation must not change logical identity. No image registration or resampling occurs at import time. Empty foreground is a valid observed mask, not a missing image.

### 4.4 Original-resolution connection algorithm

1. Discover/validate a complete model inventory and decode binary masks. Label each CNT file's foreground independently at original resolution using 4-neighbour components; do not union different CNT stack planes before extraction. Order components deterministically by their original geometry.
2. For component C at stack s, enumerate electrode assets with nonempty `C & E`. Above: sequence<s; below: sequence>s. Nearest overlapping upper is the maximal sequence<s; nearest overlapping lower is the minimal sequence>s. Equal-stack overlap cannot supply an upper/lower endpoint and is reported as an unsupported/ambiguous contact. Keep all candidates for evidence.
3. Select the nearest lower layer **before** testing the pair's common intersection. If that layer contains multiple overlapping electrode assets, mark unresolved; never skip to a deeper unique/common-overlap alternative. The same uniqueness requirement applies above. Missing either side, same bound element, equal-stack contact, or known multi-contact ambiguity yields no relation. Where an upper candidate skips an intervening modeled stack layer, record that candidate but hold its relation pending the “immediately above” interpretation; numeric gaps without modeled layers are reported as unknown stack coverage, not invented missing electrodes.
4. Require `J=C & upper & lower` to be nonempty. Separate upper/lower intersections elsewhere in C do not suffice. As a conservative proposal, multiple disconnected regions in J flag a possible undivided multi-contact CNT and remain unresolved; do not heuristically split C. This catches a known pattern but cannot prove that a connected region contains only one physical contact. Expose this residual limitation for pilot inspection.
5. Select the pixel in J closest to J's centroid, breaking exact ties by y then x. Use integer/rational squared-distance comparison to avoid traversal-dependent floating-point ties. Both endpoints reference the same original pixel centre: `[(x+0.5)*0.1,(y+0.5)*0.1]` µm. The connection mask is original C, not just J or its bounding rectangle. Emit **at most one** connection for C; resolved components emit exactly one, unresolved components emit none.
6. Run existing `validate_product` before export and `load_manifest` on the staged export. Store unresolved components and rejected deeper candidates in the report and show them in preview. A successful algorithm run is never an electrical validation result.

### 4.5 Transform and preview

Factor one shared transform description from the existing recipe, retaining identical area-resize arithmetic: `nh=max(1,round(H*G/max(H,W)))`, `nw=max(1,round(W*G/max(H,W)))`; `left=(G-nw)//2`, `top=(G-nh)//2`. Record `[nh,nw]`, left/top/right/bottom padding, and applied `sx=nw/W`, `sy=nh/H`. Original pitch remains 0.1; effective content-grid pitches are `[0.1/sx,0.1/sy]` and can differ slightly through integer rounding. Padding has no source physical extent.

For original pixel-centre index `(x,y)`, grid edge coordinates are `((x+0.5)*sx+left,(y+0.5)*sy+top)`; normalize by G for endpoint features. Inverse is `((gx-left)/sx-0.5,(gy-top)/sy-0.5)`. Report transform in grid evidence and use the shared helper in image preparation and endpoint feature construction. Round-trip tests concern continuous coordinates, not recovery of lost raster details. Keep all channels aligned; preserve original Product frame/coordinates. Grid reports at export describe the supplied candidate; search re-evaluates at checkpoint grid, so do not label an export transform as universally applied.

Preview is a self-contained offline HTML index with embedded or bundle-local generated images (no CDN/fonts/fetch) and explicit source-coordinate axes. It shows the full frame with toggleable electrode/CNT layers, a reference-only core rectangle, component IDs, resolved endpoints, selected stack pair, unresolved colours/reasons, ignored lower candidates, and a prominent “automatic extraction; electrical verification not performed” legend. Allow human zoom/pan or separate labelled display magnifications without modifying the model input. Avoid a component marker disappearing at overview scale by listing every component and linking its original-coordinate evidence. Escape source names in HTML. Do not make preview inspection an approval control that silently promotes connections. A manually inspected synthetic example must include resolved, ambiguous and margin connections and demonstrate no axis flip or wrong polarity.

## 7. Interruption, retry, and review recovery

At each accepted Task boundary, the coordinator records Task/Dispatch IDs, plan v1, base/candidate commit or diff fingerprint, changed and untracked files, exact commands/results, pending decisions and independent review candidate. This plan supplies contracts, not live lifecycle status. Reconcile copied state with Orca before acting.

Workers check coordinator messages at natural checkpoints and before exactly one `worker_done`, reporting success or failure with evidence. Heartbeats follow the dispatched preamble. A timeout or lost contact is not worker death; inspect authoritative worker state and preserve partial work. Retry only a positively failed/stopped Dispatch, keep its Task, use `--retry-of`, and never start a second editor. Do not reset, blanket-checkout, stash/pop globally, remove a worktree or discard unknown staging outputs as recovery.

For implementation failures, distinguish local bugs, environment issues and contract defects. An acceptance/specification gap returns to Astra plan revision and Opus acceptance; no worker silently changes schema or resolves user-pending semantics. Proposed file scope changes require coordinator authorization. No Codex/other-provider review substitutes for required fresh Opus 5.5 high independent review. A review PASS applies only to its exact candidate, and the author cannot issue it. Reviewers receive the accepted Task contract, diff/candidate, named counterexamples, test evidence and narrow relevant call sites.

Importer interruption recovery is deliberately separate from training resume: an unpublished staging bundle is not a model input; a published bundle must pass hash verification before reuse. Incomplete imports can be rerun into a new output directory with the same explicit options, without altering source files. Existing checkpoints remain inference-compatible only if schema/model/config/tensors are unchanged; code-hash changes after this feature correctly block resume across revisions. Keep the prior code/environment for a prior run or start a new explicitly configured run, never forge matching hashes.
