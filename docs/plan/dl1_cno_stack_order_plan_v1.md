## 3. Recommended order-file contract

### 3.1 Alternatives and recommendation

| Choice | Evaluation |
|---|---|
| Separate JSON containing one top-to-bottom reference list | **Recommend after the latest user answer.** One total order covers all models; filter absent layers per model and require every present name. No merge/override rules or image edits are needed. |
| Original proposal: default plus per-model lists | Now unnecessary because the user confirmed common order. Drop it and reject `default`/`models` fields. No concrete need for exceptions is established; contradictory future evidence requires replanning. |
| Per-CNT `between X and Y` records | Describes electrode anchors compactly, but multiple CNT layers between the same anchors have no mutual order. Missing anchors across models, extreme positions, and skipped-cno evidence require additional rules or a second ordering system. Not the smallest correct solution. |
| Add order to the existing lineage/design metadata JSON | Fewer files, but inspection would acquire coupling to metadata and require a metadata schema migration. It also contradicts the explicit separate-order-file decision. Keep metadata unchanged. |

The file is data, never executable configuration. Proposed filename: `stack-order.json`; CLI: `--stack-order PATH`. The extension is advisory; content is strict JSON. No YAML/parser dependency, includes, environment substitution, anchors, arithmetic, or path references inside it.

### 3.2 Exact schema and resolution

```json
{
  "stack_order_schema_version": "dl1_png_stack_order_v1",
  "order": ["pxl", "OCNT", "SD2", "GCNT", "GAT", "PCNT"]
}
```

This example illustrates syntax only; it is **not** a prescription of real CNT positions. Replace it with the actual common order. Required keys are exactly `stack_order_schema_version` and `order`, with no optional fields. Version is the exact string above. `order` is an array of exact, unique layer-name strings; an empty array is structurally valid but fails missing-name validation for a model with electrode assets. Reject duplicate JSON keys, unknown keys (including `default` and `models`), wrong types, nonfinite constants, invalid strings, and unsupported versions. Validate the entire reference list before filtering.

Name validity uses the existing nonempty, trimmed identifier rule (`schema.py:18–21`), additionally rejecting control characters (U+0000–U+001F/U+007F) and unpaired surrogates in order-file identifiers. Preserve exact Unicode, case, punctuation, and remaining suffix spelling; do not trim, case-fold, normalize NFC/NFD, or treat names as paths. JSON escaping represents the same decoded name; genuinely different Unicode sequences stay different. Diagnose duplicates before filtering so repeated absent names cannot be hidden.

For each source-valid model when a file is supplied (required for cno-present models):

1. Use the single `order` reference for every model. There are no per-model overrides or inferred aliases.
2. Build distinct electrode layers from electrode filenames, with number and all electrode asset references, and distinct CNT names from cno suffixes. Do not consult CNT pixels to determine order.
3. Keep same-name cno files separate at one named layer; identify each by name plus decoded full-mask hash (§4.2). Same-name/same-mask files create an indistinguishable-identity edge case, explicitly handled in §6; never merge them or use their prefix to break the tie. Reject an electrode name mapped to multiple electrode numbers, or one name used by both electrode and cno layers. A list of names cannot represent these ambiguities. Multiple electrode assets sharing the same name **and number** are one layer and are allowed.
4. Filter the reference list to names present in this model. Retain filtered-out entries in `ignored_names`, in input order, as audit evidence rather than errors. They create no placeholder positions or skipped layers. A typo of a required name still yields a missing-name error.
5. Require every distinct electrode layer and CNT name present in the inventory exactly once in the reference list; multiple same-name CNT assets share that one position. Compare the electrode subsequence with increasing electrode filename numbers. Every pair must agree; numeric gaps are legal. Do not require electrode numbers to become contiguous.
6. Assign zero-based `order_index=0..n-1` to the filtered mixed list, top to bottom. CNT before the first or after the last electrode is valid order input; the corresponding component may lack an endpoint and remain unresolved. Adjacent CNT layers are permitted.

Missing `cno` means order is `not_required`; old no-cno inspection/export remains usable without this file, with the existing electrode numeric ordering and absent-CNT reason. Without a supplied order file, do not newly reject such a model for a names-only ambiguity irrelevant to CNT extraction. If a file is explicitly supplied, validate reference coverage and electrode order for every model, including no-cno models: the new user answer says a present name absent from the reference is an error. Valid no-cno models can then have `status=resolved` and an electrode-only resolved order; `not_required` applies when no file is supplied. The legacy no-cno path gains no missing-file gate. An empty `cno` directory counts as present: require the file, resolve its electrode-only list, and retain `present_cno_without_png_assets`. All-white CNT files still require their names in the order. These conservative choices enforce the requested “export with cno present” gate without claiming absence is electrical evidence.

### 3.3 Errors, exact diagnostic templates, and severity

Order issues have stable codes plus the exact message templates below; placeholders use JSON-quoted names, sorted name/path lists, zero-based list indexes, and source-root-relative POSIX paths. Put order-file failures under diagnostic path `stack_order`, without leaking its absolute host path. A model-specific message includes the exact model ID. A single implementation helper may format these as `CODE: message` in existing `SourceIssue.reason`; no core schema change is needed.

| Violation | Code and exact message template |
|---|---|
| File unreadable/directory/missing | `stack_order_read_error: cannot read stack order file ({exception_class})` |
| Not UTF-8, including UTF-16 | `stack_order_encoding: expected UTF-8 with optional leading BOM` |
| Invalid JSON/trailing content/comments | `stack_order_json: invalid JSON at line {line}, column {column}` |
| Duplicate key anywhere | `stack_order_duplicate_key: duplicate key {key}` |
| NaN/Infinity/-Infinity | `stack_order_nonfinite: invalid JSON constant {token}` |
| Root not object | `stack_order_schema: expected object` |
| Missing/extra root fields | `stack_order_fields: required ["order", "stack_order_schema_version"]; missing {missing}; unknown {unknown}` |
| Wrong version/type for version | `stack_order_version: expected "dl1_png_stack_order_v1", got {value}` |
| List is not array | `stack_order_list_type: {location} must be an array of layer names` |
| Invalid/non-string list element | `stack_order_identifier: {location} must be a nonempty trimmed identifier without controls or unpaired surrogates` |
| Repeated name in a list, including absent names | `stack_order_duplicate_name: {location} repeats {name} at indexes {indexes}` |
| Same CNT name and identical decoded full masks | `ambiguous_cnt_asset_identity: model {model}, CNT {name}, mask_sha256 {hash}, files {paths}; separate stable source identifiers are required` (§6). Different-content same-name files are accepted. |
| Same electrode number has different names | Retain electrode-only `conflicting stack {number}; also {path} ({name})` source diagnostics and both relevant file paths in inventory; cno numbers never enter this check. |
| Electrode name at multiple numbers | `stack_order_ambiguous_electrode_name: model {model}, layer {name}, electrode numbers {numbers}, files {paths}` |
| Electrode/CNT namespace collision | `stack_order_name_kind_collision: model {model}, name {name}, electrode files {electrode_paths}, CNT files {cnt_paths}` |
| Required electrode omitted | `stack_order_missing_electrode_names: model {model}, missing {names}` |
| Required CNT omitted, including empty foreground | `stack_order_missing_cnt_names: model {model}, missing {names}` |
| Electrode subsequence reverses number order | `stack_order_electrode_order_conflict: model {model}, listed {listed_pairs}, expected {numeric_pairs}` where each pair is `[name, electrode_number]`. |
| No order file, cno present | Nonfatal inspection requirement `stack_order_required: model {model}; supply --stack-order for CNT placement` |

Existing PNG syntax, duplicate electrode binding, decoder, shape, and containment errors retain their behavior. Change the filename parser's wording from “positive stack prefix” to “positive numeric prefix” so it is correct for both kinds. Deterministic validation order: read/encoding/JSON, root fields/version/types, identifiers/list duplicates, then per-model inventory ambiguities, missing names, electrode order. Aggregate independent per-model issues; never resolve or extract a model with a listed issue. A malformed file blocks all cno model extraction; a valid reference that cannot resolve a model blocks that model and all-model export, but valid other models may still be inspected. Unknown globally unused layer names are allowed and listed, not hard errors; this is necessary for a shared reference whose layers may be absent from imported models.

### 3.4 Windows handling and immutable input evidence

Read the file **once as bytes**, compute SHA-256 on those exact bytes, decode with `utf-8-sig`, and parse that same snapshot with duplicate-key and nonfinite rejection. Accept LF/CRLF and an optional single leading UTF-8 BOM; reject double/embedded BOM outside JSON strings as JSON syntax errors. Reject UTF-16/UTF-32 BOMs and raw NUL bytes before decoding with `stack_order_encoding`; invalid UTF-8 yields the same error. Raw hash intentionally differs for BOM/newline changes, while resolved order and semantic identities remain equal. Never use universal-newline-translated text for the raw file hash.

Use native `pathlib.Path` for the CLI argument (Windows absolute/relative paths, spaces, and Korean names); quote paths in Windows commands. Do not split the argument on backslashes, colons, or whitespace or interpolate it into a shell. A Windows path is exercised as Windows only on Windows, not by claiming macOS can open a `D:\...` string. Portable tests can assert argparse preservation and path-independent parsing using a temporary native path with spaces/Korean characters. Keep the file outside the PNG source tree in documentation to avoid unrelated-file/layout inventory warnings. Do not copy arbitrary absolute paths into the report. Changing the file on disk after reading cannot change the parsed order or recorded raw hash for this invocation.

## 6. Confirmed follow-up and remaining decisions

The latest user answers settle two original questions: repeated CNT names are allowed without merging files; one reference order covers all models and absent layers are normal. This plan removes the original duplicate-name error and per-model lists; no concrete need for overrides remains.

Three remaining decisions, with conservative defaults:

1. **CNT names outside OCNT/GCNT/PCNT:** accept any valid exact suffix covered by the reference order. The known names are not a confirmed closed vocabulary; the algorithm has no name-specific physics. A whitelist rejects synthetic C4/C6 and future legitimate names without proving correctness. A requested allowlist would be validation only, never default positions.
2. **Indistinguishable same-name files:** name plus full mask hash distinguishes different-content same-name assets. If two have identical decoded masks (including re-encoded identical PNGs or all-white masks), no content-based rule can bind stable distinct identities to individual files under arbitrary renumbering without an additional persistent identifier. Default: `ambiguous_cnt_asset_identity` naming both/all files; no union, dropping, or number/path tie-break. This is an explicit open edge case, not rejection of all repeated names. Alternatives require a user-approved stable per-asset ID mapping in a separate versioned contract, or acceptance of multiset-only identity that loses per-file provenance continuity. Neither is silently implemented.
3. **`same_electrode_required`: unconfirmed.** The reported premise is that an electrode uses the same folder name across layers and different names never mean the same net. The coordinator must confirm whether every valid CNT therefore joins equal electrode-folder names, including intended cross-electrode connections, shorts, aliases and incomplete observations. **Default false: preserve the current rule.** The premise alone does not authorize different extraction results.

### Optional same-electrode rule analysis (decision-gated)

Current selection finds globally nearest overlapping upper/lower layers, then requires one electrode on each. Unique A-upper/B-lower can emit if geometric checks pass. If approved, the smallest alternate selector is:

1. Select exactly the same nearest overlapping layer indices first, without filtering by electrode name; retain all candidates.
2. Form upper/lower pairs with equal exact electrode-folder names. No aliases, overlap-size preference, or alphabetical choice.
3. Exactly one same-name pair proceeds to existing common-intersection and representative-pixel checks, even when unmatched electrodes also overlap the selected layers. Record those exclusions. Zero same-name pairs yields `no_same_electrode_pair_on_selected_layers`; multiple matching pairs yields `multiple_same_electrode_pairs_on_selected_layers`. Neither emits a relation.
4. A unique pair failing the geometric checks stays unresolved; never search deeper for a matching name or fall through to another pair. Filtering by electrode before finding layers could jump through an intervening conductor and changes the nearest-layer rule; that stronger alternative is not recommended without separate domain confirmation.

This could resolve upper `{A,B}` / lower `{A}` to A/A while rejecting unique A/B. Upper `{A,B}` / lower `{A,B}` remains ambiguous. Risks: equal folder names are asserted semantics, not electrical proof; the filter could hide real cross-electrode defects/contacts, discard competing conductors to make a misleading unique pair, or fail on inconsistent names. It changes coverage, IDs and model input. Confirmation must cover ambiguity resolution as well as cross-electrode rejection.

For these two Tasks, add report parameter `same_electrode_required: false` at top level and per extraction, validate it as false for algorithm 2, and test default behavior in O18. **Do not add an active CLI switch or alternate selector until confirmed.** If confirmed before implementation, coordinator adopts a revised contract with option/default, reasons and tests; if introduced after algorithm 2 is published, bump algorithm version again and obtain independent review. The reference-order schema is positional and must not silently encode contact physics.

Names-only ordering also rejects within-model electrode/CNT kind collisions and electrode names repeated at different numbers. These are explicit representational limitations, not claims about unseen data. Skipped-layer physical confirmation remains unverified.
