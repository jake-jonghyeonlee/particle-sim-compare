## 차단 항목 (PLAN_v2에서 반드시 수정)

B1. **DL2 학습의 기본 방식이 사용자 결정과 다르다.** T11은 "supervised relation loss를 기준"으로 적었다. 사용자와 정한 방향은 정답 없이 시작하는 것이다: 같은 위치를 조금 다르게 잘라 본 두 장을 가깝게 두는 대조 학습이 기본이고, ROI 대응 정답은 폐쇄망에 있을 때 얹는 선택 사항이다. 다른 위치의 닮은 구조를 과하게 밀어내지 않도록 하는 손실 설계와 그 반례를 T11 계약에 넣는다. hotspot 예측 보조 학습은 선택 사항이며 v1 범위 밖으로 명시한다.

B2. **DL2에 넣을 검토 ROI를 누가 만드는지가 없다.** T12는 DL 결과를 C가 읽는 방향만 다룬다. C에서 DL2로 가는 방향, 곧 검토 ROI 목록의 내보내기 계약이 없다. v1의 ROI 출처는 (a) 전극 수 지도의 영역(T5)과 (b) 사용자가 직접 지정한 위치로 한정하고, 내보내기 형식과 그 Task(T6 또는 새 Task)를 정한다. 제품 간 구간 대응으로 ROI를 고르는 것은 이번 계획에 없으므로 그렇게 적는다.

B3. **2026-10-06에 합의한 불량 종류별 조각 분해의 처리가 빠졌다.** 합집합을 lateral만 / vertical만 / 동시로 나누는 지표다. line/pixel 분류와는 다른 축이다. v1에 넣을지 뺄지를 명시하고, 뺀다면 non-goal에 적는다. coordinator 의견: T3에서 pair membership을 이미 유지하므로 불량 종류 표시를 case에 보존하는 것까지만 하고, 종류별 조각 지표 자체는 v1 non-goal로 둔다. 사용자 확인 대상(G7)으로 올린다.

## 권고 항목

A1. 단계 구분을 넣는다: 1단계 수치(T1~T7), 2단계 DL1(T8~T9), 3단계 DL2(T10~T11), 4단계 인수(T12). 단계마다 사용자에게 보고하고 다음 단계로 간다.
A2. 독립 Opus 검토를 묶는 단위를 미리 정한다: 수치 계산(T2~T5)을 한 후보로, CLI·리포트·폐기(T6~T7)를 한 후보로, DL1(T8~T9), DL2(T10~T11), 인수(T12).
A3. 전극 수 지도를 short만 받도록 한 것은 사용자 확인이 필요하다(G7에 함께). 기록에는 open이 전극 하나로 들어가는 예가 있었고, 수율 계산에서 open을 뺀 이유(실측에 거의 없음)가 지도에도 그대로 적용되는지는 정해지지 않았다.
A4. T2의 Target이 옛 `schema.py`·`preprocess.py`·`adapters/example.py`를 고치게 되어 있다. T7에서 지울 파일과 겹치지 않는지, 새 모듈(`adapters/numeric.py`, `measurement.py`)만으로 닫을 수 있는지 다시 본다. 옛 파일을 고쳤다가 지우는 일은 피한다.
A5. G5(DL1 입력 방식)는 사용자가 "학습에 유리한 방향으로 추천"을 요청해 받은 권고이고 명시 승인은 없었다. 게이트로 둔 것은 맞다. 다만 겹침 버그 수정과 검증기 같은 답변 비의존 작업은 진행 가능하다고 이미 적혀 있으므로 그대로 둔다.
