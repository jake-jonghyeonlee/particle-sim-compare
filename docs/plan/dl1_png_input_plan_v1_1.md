## 4. Contract choices and recommended design

### 4.1 Adapter boundary and missing metadata

| Alternative | Benefits / cost | Decision |
|---|---|---|
| Export existing strict v1 manifest and NPY assets; separate versioned import report | Reuses all validators, train/search, checkpoint configuration and path safety; requires explicit lineage/design/grid before model-ready export | **Recommend for v1.** Automatic generation means the program writes the manifest, not that it invents missing metadata. |
| Extend manifest to accept PNG plus stack/provenance/new extent fields | Requires new schema version, dual-version loader and checkpoint policy; mixes source decoding with tensor loading | Defer; only revisit through a reviewed v2 plan if actual limitations require it. |
| Relax v1 to accept null metadata/grid or unknown extra fields | Makes incomplete imports look trainable, weakens existing strictness and provenance | Reject. |

Proposed CLI is `python -m psdl1.import_png --root ROOT --out OUTPUT`, defaulting to inspection. Optional `--inspect-grids G [G ...]` evaluates only explicitly supplied positive integer grids; there is no default or automatic selection. Optional `--png-max-image-pixels N` explicitly sets the finite positive Pillow pixel threshold for this invocation (§4.3). It always attempts a versioned report and preview for valid models, without requiring lineage/grid. Add `--export --metadata METADATA_JSON --candidate-grid G` to generate `OUTPUT/manifest.json` and contained `assets/*.npy` automatically. CLI spelling is a proposal to freeze at T1 acceptance, not an existing command.

Metadata JSON has a versioned strict schema (e.g. `dl1_png_metadata_v1`) and exact `models` mapping from source model names to user-provided `lineage_id` and `design_version`; no labels, split, hotspot, default grid, or inferred IDs. Reject duplicate keys, unknown model keys and invalid strings; missing model entries block export. Partial metadata is permitted in inspection and listed as pending; export requires every discovered model to be valid and mapped. Missing export metadata/grid produces a diagnostic report and nonzero result **without publishing a model-ready manifest**. This intentional prerequisite must be visible in CLI help and docs, not discovered only after a loader failure. A future demand for trainable manifests without that metadata requires explicit contract replanning.

Use output outside the input tree; never modify original PNGs. Export all requested models or none: invalid files must not silently disappear from the training pool. Unresolved relations are not invalid images and may be represented as partial/unavailable while preserving global CNT geometry. New output bundle only; refuse an existing destination rather than replacing user files. Build in a sibling staging directory, validate assets and manifest there, then publish the directory atomically. A failed/blocked import may publish a clearly diagnostic-only report/preview bundle, never a stale or partial `manifest.json`. Reruns use a new output destination. Interruption leaves identifiable staging output for explicit inspection, not automatic deletion. Exported element, valid, global CNT and connection NPY masks use `bool` dtype; the unchanged loader still converts them to float32. The inspect report exposes the resulting resource cost before export (§4.6).

### 4.2 Frame, IDs, status, and sidecar

Keep `SCHEMA_VERSION`, `MODEL_INPUT_VERSION`, NPY encoding, endpoint feature dimension, and model weights format unchanged. `unit_size_um=[W*0.1,H*0.1]` is a compatibility field for full input extent; document that it does **not** assert a single physical unit. Sidecar explicitly records `comparison_scope: full_frame`, `frame_extent_um`, `core_bbox_xyxy_px:[500,500,W-500,H-500]`, `core_layout:[2,2]`, `single_unit_extent_um:null`, original `shape_yx`, pitch 0.1, local edge origin `[0,0]`, and model-wide stack table. Reject W≤1000 or H≤1000 under this source contract. No bbox drives input transforms.

For size semantics, the alternative is a v2 rename from `unit_size_um` to `frame_extent_um` plus an optional separately supplied physical-unit field; that is clearer naming but entails loader/model-fingerprint migration and explicit rejection or conversion of older checkpoints. Recommend the documented v1 compatibility alias plus sidecar for this feature because the current validator already enforces full extent. Never put a guessed single-unit or core size into the old field. Likewise, adding stack/provenance directly to `Element`/`Product` is a possible explicit v2 contract revision, not an allowed unknown-field extension to v1.

Product ID is the unchanged model folder name; electrode ID and default role are unchanged electrode folder names; actual layer is the full suffix after the first separator. Preserve stack separately in the sidecar. Same sequence with different layer names anywhere in a model is an error; duplicate electrode×layer assets are errors even if names differ in zero padding/separator. Repeated actual-layer names at different stack positions must be reported; if they collide with a v1 binding, block export rather than merging or renaming layers. Do not case-fold or trim source names into accidental aliases: reject invalid identifiers with path diagnostics.

The inspect report lists sorted role and layer sets per model, their cross-model union, and each name occurring in only one model (count models, not asset occurrences). These sets help users detect incompatible vocabularies; inspection without a checkpoint cannot certify vocabulary coverage. `role=electrode folder name` means that names absent from the checkpoint training vocabulary cannot be embedded. Reused names share the model embedding but imply no independently established electrical/functional equivalence. USAGE must state both consequences. Optional explicit role/layer alias mapping remains out of scope and pending; do not silently map unknown symbols. Preserve existing search behavior: an out-of-vocabulary query is unavailable with named reasons, candidates are explicitly listed as excluded, and direct `embed`/preparation raises a clear error. None is silently dropped.

Element/frame/component/connection IDs are derived from canonical source tuples and binary geometry, never directory enumeration, absolute root path, or Python hash. Specify canonical JSON plus SHA-256 for filename-safe IDs; collision check emitted IDs. Component identity includes model, numeric CNT stack, exact CNT layer, source asset binding and its original-coordinate component pixels. Preserve original filename/relative path separately; equivalent separator/zero-padding spellings must normalize the binding consistently. File-byte hashes and canonical binary-mask hashes serve different provenance roles. A renamed/re-encoded file can change source inventory hashes without changing logical relationships.

`import-report.json` uses explicit `report_schema_version: dl1_png_import_v1`, metadata schema, algorithm ID/version, component neighbourhood and pending policy. Include per-file path, byte hash, decoded mode/shape, binary mask hash/polarity; model IDs/stack table; vocabulary sets/union/unique names; `resource_estimate` per model; decoder effective pixel limit and explicit override provenance; geometry/valid assumption; each component's bounds/pixel count/hash, full above/below overlap candidates, selected candidates, ignored lower candidates with reason, `skipped_upper_layers` and `skipped_lower_layers` with intervening electrode and cno layers listed separately, per-relation confirmation flag and summary counts, common-intersection evidence, both endpoint references and pixel/µm coordinates; unresolved reasons; errors/warnings; metadata/grid readiness; extraction/export status; generated manifest hash, asset hashes and Product input identities when exported. Reject unsupported report versions when reading a report for preview/verification. Stable payload/order should reproduce; omit timestamps or keep them outside identity-bearing content.

Store `electrical_verification: not_performed` and `real_data_validation: not_performed` prominently. `observation: observed` on a generated relation means its source masks are observed, never electrically verified. When at least one component is resolved and others unresolved use `connectivity_observation: partial`; zero resolved means `unavailable`, including no/empty CNT source. If all nonempty components resolve under the recorded rule, `complete` can describe **extraction coverage only**, with sidecar explicitly saying so and `electrical_verification` unchanged. Missing `cno` and present-but-empty/white-only CNT are distinct report reasons; neither establishes verified absence. Global `cnt` is the union of **all** decoded CNT foreground, including unresolved components. Do not fill missing endpoint objects to make an unresolved relation fit v1.

`connectivity_observation` is not merely display metadata: `train.py:106` maps unavailable/partial/available to model indices and `model.py:99` defines the three-way embedding added to the product representation. Changing automatic extraction coverage from partial to complete therefore changes model input and identity even with otherwise equal masks. USAGE must put this fact next to the exact wording **“complete means extraction coverage only; electrical verification not performed.”** A skipped-layer “needs confirmation” flag is sidecar/preview evidence, not an extra model-status category: if all components resolve under the specified rules, coverage is complete despite pending physical confirmation. Do not relabel it electrically verified or silently force partial in place of the defined aggregation rule.

The sidecar is outside the strict model manifest and is delivered with the export bundle. Export validation binds it to manifest/assets by hashes and a `--verify-bundle` importer mode checks those links without source PNGs or network. Legacy NPY manifests can still load without a sidecar; no claim is made that arbitrary consumers retain provenance after users detach the report. Train/checkpoint input identities describe model input, not the entire original PNG inventory. Do not inject report fields into model features.

### 4.3 Strict source decoding

Use Pillow, lazily imported by the PNG adapter so legacy NPY use remains independent. Declare a PNG optional dependency in `pyproject.toml` using the already-tested locked Pillow version/range; no lock refresh/download is necessary. Reuse NumPy and standard library for component labeling, not an undeclared SciPy/OpenCV dependency.

Support single-frame PNG modes `1`, `L`, `RGB`, `LA`, `RGBA`, and palette `P` only when decoded pixels are exactly black/white and every alpha value is fully opaque. Validate RGB channels, palettes and transparency after exact decoding, with no luminance conversion, colour/gamma adjustment, EXIF transpose, or threshold. Reject intermediate grey, coloured pixels, transparent/semitransparent pixels (including alpha=0), unsupported bit-depth/modes, corrupt/truncated files, multi-frame PNG, or nonidentity orientation metadata with individual paths/reasons. Fixture-confirm the actual Pillow mode behavior; no blanket “all PNGs supported” claim. Pillow's decompression-bomb warning and error both become per-file import errors: record dimensions/pixel count when available, exception class, effective `Image.MAX_IMAGE_PIXELS` and Pillow version. Preserve Pillow's installed default unless the user explicitly supplies `--png-max-image-pixels N` as a finite positive integer; record both default and requested/effective values and never use `None` to disable the guard. This option changes only this import invocation, restores the prior global value in `finally`, and performs no parallel decoding while the global override is active. It is an explicit user-controlled override, not a real-resource acceptance threshold. Actual default and warning/error behavior are inspected from installed Pillow and fixture-tested; no numeric default is invented. A patched-low-limit test must cover both warning-to-error and hard-error cases plus explicit sufficient override, with no silent retry at a higher limit.

All files named `.png` at the expected depth are checked; malformed names, duplicate normalized bindings, conflicting stacks, shape mismatches, unsupported layouts and escaping source symlinks are errors. Ignore unrelated non-PNG files only with an inventory warning. Source root relocation must not change logical identity. No image registration or resampling occurs at import time. Empty foreground is a valid observed mask, not a missing image.

### 4.4 Original-resolution connection algorithm

1. Discover/validate a complete model inventory and decode binary masks. Label each CNT file independently once at original resolution using 4-neighbour components; keep a label array and component bounding boxes, pixel counts and local offsets. Never union different CNT stack planes before extraction. Order components deterministically by original geometry. All per-component candidate tests, intersections, hashes/representative-pixel work use bbox slices (§4.6).
2. For component C at stack s, enumerate electrode assets with nonempty local `C & E`. Above: sequence<s; below: sequence>s. Nearest overlapping upper is the maximal sequence<s; nearest overlapping lower is the minimal sequence>s. Keep all candidates for evidence. Equal-stack overlap cannot supply an upper/lower endpoint. The reachable equal-stack ambiguity is an electrode and cno asset with the **same sequence and same layer name**; if the names differ, inventory validation already rejects the model. A same-name equal-stack overlap is conservatively unresolved and explicitly tested.
3. Select the nearest lower layer **before** testing the pair's common intersection. Multiple overlapping electrodes on that selected layer remain unresolved; never skip to a deeper unique/common-intersection alternative. The same uniqueness requirement applies above. Missing either side, same bound element, equal-stack contact or known multi-contact ambiguity yields no relation. A unique nearest overlapping upper may skip modeled nonoverlapping layers: **emit the relation when all other rules hold**. Populate `skipped_upper_layers` and symmetric `skipped_lower_layers` for each emitted relation. Each has separately sorted `electrode_layers` and `cno_layers` entries with sequence/name/source references; summaries count flagged relations by direction and intervening electrode/CNT layers distinctly. Set a sidecar `needs_confirmation` flag and show it in preview; it does not suppress an otherwise valid relation. Numeric gaps without modeled assets are not invented missing layers.
4. Require bbox-local `J=C & upper & lower` to be nonempty. Separate upper/lower intersections elsewhere in C do not suffice. As a conservative proposal, multiple disconnected regions in J flag a possible undivided multi-contact CNT and remain unresolved; do not heuristically split C. This detects a known pattern but cannot prove that a connected region contains only one physical contact; expose that residual limitation for pilot inspection.
5. Select the pixel in J closest to J's centroid, breaking exact ties by y then x; use integer/rational squared-distance comparison to avoid traversal-dependent floating-point ties. Add bbox offsets to obtain original coordinates. Both endpoints reference the same original pixel centre: `[(x+0.5)*0.1,(y+0.5)*0.1]` µm. The connection mask represents original C, not just J or its rectangle. Emit **at most one** connection for C; resolved components emit exactly one, unresolved components none. Store compact component geometry during extraction; materialize a full-frame bool mask only for the compatibility consumer/export boundary.
6. Run existing `validate_product` before export and `load_manifest` on staged export. This boundary retains its existing full-frame costs; expose them in advance, never conceal them as a streaming loader. Show unresolved components, skipped-layer confirmation flags and rejected deeper candidates in report/preview. A successful algorithm run is never an electrical validation result.

### 4.5 Transform and preview

Factor one shared transform description from the existing recipe, retaining identical area-resize arithmetic: `nh=max(1,round(H*G/max(H,W)))`, `nw=max(1,round(W*G/max(H,W)))`; `left=(G-nw)//2`, `top=(G-nh)//2`. Record `[nh,nw]`, left/top/right/bottom padding, and applied `sx=nw/W`, `sy=nh/H`. Original pitch remains 0.1; effective content-grid pitches are `[0.1/sx,0.1/sy]` and can differ slightly through integer rounding. Padding has no source physical extent.

For original pixel-centre index `(x,y)`, grid edge coordinates are `((x+0.5)*sx+left,(y+0.5)*sy+top)`; normalize by G for endpoint features. Inverse is `((gx-left)/sx-0.5,(gy-top)/sy-0.5)`. Report transform in grid evidence and use the shared helper in image preparation and endpoint feature construction. Round-trip tests concern continuous coordinates, not recovery of lost raster details. Keep all channels aligned; preserve original Product frame/coordinates. Grid reports at export describe the supplied candidate; search re-evaluates at checkpoint grid, so do not label an export transform as universally applied.

Optional inspect `--inspect-grids G [G ...]` runs existing `grid_check` for each user-supplied grid on typed source Products (lineage/design may remain absent for inspection; do not fabricate them). Record per-grid resampling/narrow-line/bridge evidence and the exact rounded transform/effective pitch above. No supplied grids means no grid evaluation and no model-grid suggestion. Multiple supplied grids remain comparison evidence, never automatically choose a winner or mark one approved. The report can guide a later explicit `--candidate-grid` export. Resource estimates are generated and surfaced before optional full-frame grid evaluation, whose memory/time cost follows the legacy Product representation (§4.6). Failures leave diagnostic reports. T3 computes the documented recipe for inspection; T4 replaces any interim duplicated recipe with the single shared helper so inspect/export/train all report consistent values.

Preview is a self-contained offline HTML index with embedded or bundle-local generated images (no CDN/fonts/fetch) and explicit source-coordinate axes. Raster previews use **Pillow only** plus existing NumPy/stdlib, not matplotlib or an added plotting dependency. Produce a downscaled full-frame overview with the display scale recorded, and a one-source-pixel-per-preview-pixel crop for every CNT component (with source bbox offset and applicable electrode overlays). These **display crops are for human inspection only; model input always retains the full frame**, stated in the legend. It shows the full frame with toggleable electrode/CNT layers, a reference-only core rectangle, component IDs, resolved endpoints, selected stack pair, unresolved colours/reasons, a distinct “needs confirmation” style for emitted skipped-layer relations, separate intervening electrode/cno layer lists, ignored lower candidates, and a prominent “automatic extraction; electrical verification not performed” legend. Allow human zoom/pan or separate labelled display magnifications without modifying the model input. Avoid a component marker disappearing at overview scale by listing every component and linking its original-coordinate evidence. Escape source names in HTML. Do not make preview inspection an approval control that silently promotes connections. A manually inspected synthetic example must include resolved, ambiguous and margin connections and demonstrate no axis flip or wrong polarity.

### 4.6 Extraction cost and inspect resource estimates

For N=H×W, E electrode assets and K CNT components, allocate one label array per CNT source file, obtain component boxes in the labeling pass, and evaluate component c only within its area A_c. Avoid a naive full-frame `labels==c` allocation or `C & E` scan for every component/electrode. Candidate/intersection work is proportional to the sum of inspected bbox areas times electrode candidates, plus source decoding/labeling; widely spanning components may still be expensive, so do not promise a universal sublinear bound. Component identity must hash canonical local pixels plus original bbox/shape, not a newly materialized full-frame raster. Full file/mask hashing is done once per asset. Use existing NumPy/stdlib algorithms (e.g. horizontal-run union/find), with no undeclared SciPy dependency.

The accepted v1 compatibility route still requires **one full-frame connection mask per emitted relation**, so disk export and the unchanged loader remain O(R×H×W) for R resolved components. This is explicitly not solved by bbox-local extraction. Materialize/write one bool connection mask at a time, release it, and avoid retaining K full-frame component arrays in the importer. Source, valid and global CNT exported NPYs also use bool. `load_manifest` expands all loaded masks to float32 and performs further validation/grid copies. Do not claim bool exports bound loader peak memory or make it streaming.

Before any export, inspect includes `resource_estimate` per valid model: frame shape/pixels N, electrode asset count E, CNT file/component count K, resolved relation count R, number of generated mask assets, projected bool-NPY export bytes, projected `load_manifest` retained float32 mask bytes, and an all-components-resolved upper scenario. For an export with one valid mask and optional global CNT indicator U (0 or 1), generated masks M=E+1+U+R; payload bytes=N×M×`np.dtype(bool).itemsize`; loader retained mask bytes=N×M×`np.dtype(float32).itemsize`. Calculate NPY header overhead using NumPy's actual header encoding (in memory), include it in projected NPY export bytes, and clearly exclude manifest/report/preview bytes from that estimate or report them separately. The K scenario replaces R with K, not a guessed contact count. Report that temporary arrays, labels, decoder buffers, Python objects, grid tensors and repeated validation allocations add overhead; this is **not peak RAM or runtime prediction**. Invalid/undecodable inputs get unknown estimates with reasons, never zero estimates masquerading as safety.

Inspect writes/surfaces these estimates before optional grid evaluation or export-sized allocations; it can finish without lineage, design metadata or grid. USAGE directs the user to decide real resource suitability from this evidence. No real image-size, CNT-count, memory or runtime limit is invented. S23 uses **2000×2000 or larger** synthetic frames and **300 or more** distinct CNT components to verify bbox extraction and estimates without exporting/loading hundreds of full frames. Its generous test-only wall-clock regression bound is recorded with hardware/environment and covers labeling/extraction/estimate generation, not disk export/model inference.
