이 저장소는 세 저장소 묶음의 C(compare)다. C는 수치를 계산하고, 별도 저장소 DL1(particle-sim-dl1, 원본 구조로 제품 후보 검색)과 DL2(particle-sim-dl2, 사용자가 고른 위치와 비슷한 ROI 검색)가 학습·검색을 맡는다. DL 점수는 C의 수치 옆에 표시만 하고 어떤 계산에도 들어가지 않는다.

지표는 서로 다른 축이며 하나로 합치지 않는다. line / pixel 면적, pair exclusive / shared, transfer, 세 failure pieces(lateral_only / vertical_only / simultaneous), 전극 수 지도, fraction_of_frame, 국부 ΔCA는 각각 독립 출력이다. 관측 0은 available 0이고 누락(missing)과 적용 제외(not_applicable)는 별도 상태로 구분한다.

2배경과 문제 정의

2.1 도메인

디스플레이 패널 공정에서 지름 1~50 µm 이물이 전극 사이에 떨어지면 short(또는 open)이 난다. particle-sim(별도 저장소)은 전극 layout 이미지 위에 이물 중심을 옮겨 가며 short가 나는 위치의 궤적을 hotspot(binary mask)으로 만들고, 그 면적을 CA(critical area, µm²)로 낸다. 한 case는 불량명-전극1-layer1-전극2-layer2 다섯 필드이며 지름 조건은 1~30, 40, 50의 32개다.

설계자가 알고 싶은 것은 두 수준이다.

  • 제품 수준: 어느 설계가 더 안전한가. 제품마다 unit 크기가 달라 CA 절대값은 비교할 수 없으므로 측정 2×2 frame 면적으로 나눈 단위 없는 비율(fraction_of_frame)을 쓴다.
  • 국부 수준: 이 형상 변경이 불량 유형별 CA를 얼마나 바꿨나. 비슷한 제품끼리 설계자가 짝지은 대응 위치 주변의 같은 물리 창(µm) 안에서 CA를 재고 b − a를 낸다(compare-windows).
CA / 2×2 면적 = (면적당 구조 수) × (구조 하나당 CA) ↑ 유닛 크기·pitch ↑ 형상 변경 ← 설계자가 보려는 항 제품 수준: F(d) = CA(d) / frame_area (fraction_of_frame) 국부 수준: ΔCA_w(d) = CA_w,B(d) − CA_w,A(d), 같은 물리 창 w (local_delta) 연결: Σ ΔCA_w × repeats_per_frame / frame_area vs ΔF (explained_fraction)

출처: docs/plan/PLAN_v3_local_delta_ca.md §0, docs/implementation_memory.json local_delta_ca_2026_10_18

2.2 설계 원칙

  • 원본 mask를 그대로 잰다. resize·warp·확률 union·재팽창 없음. frame의 pitch, origin, valid가 호환될 때만 같은 group에서 union한다.
  • fail-closed. 사용자 답변이 없는 값(밀도 단위, 한 unit 환산, 창 크기)은 코드 기본값으로 넣지 않는다. 2×2 mask를 자동으로 /4 하지 않는다.
  • 상태와 사유를 보존한다. 모든 지표는 {value, partial_value, unit, status, reasons, coverage, basis}를 가지며 partial/unavailable이면 value는 null이다. CSV도 null을 0이나 빈칸으로 바꾸지 않는다.
  • ID는 raw 그대로. case ID, 전극 ID, pair key의 문장부호·대소문자·Unicode를 바꾸지 않고 delimiter로 분해하지도 않는다. 복합 source identity 8 필드로 join한다.
  • 제품 간 좌표를 겹치지 않는다. 각 제품은 자기 frame에서 따로 측정하며 overlay·정합(registration)은 하지 않는다.
  • DL은 보조. DL1/DL2는 위치와 후보를 찾는 도구이고 점수는 provenance 표시용이다.

4.2 의존성

런타임: numpy ≥ 1.26, pandas ≥ 2.1, pyarrow ≥ 14, zarr ≥ 3, pillow ≥ 10.0, pyyaml ≥ 6.0. 개발: pytest ≥ 8. pyarrow·zarr는 legacy particle-sim 검사 wrapper 때문에 남아 있다. strict PNG 동작은 lock의 Pillow 12.3.0에서만 실행 검증했으므로 폐쇄망 설치는 lock 버전을 쓴다. scipy·torch 의존성은 없다(연결 성분은 자체 구현).

6.1 numeric_v2 핵심 규칙

  • identity: (product_id, design_version, source_id, process_step_id, exposure_id, case_id, frame_id, source_contract_version) 8 필드 복합 키. 제품마다 반복되는 case ID만으로 join하지 않는다.
  • endpoint: (electrode_id, role, actual_layer)를 하나의 결합 객체로 보존. 순서를 바꿀 때 객체째 옮기며 role/layer를 서로 바꾸지 않는다.
  • pair 표: unordered 전극 ID 집합 → class = line | pixel. layer/role/failure_type은 분류 key가 아니다. 미매핑은 unmapped_pair로 남기고 0이나 pixel로 추정하지 않는다.
  • frame: origin_xy_um, pixel_pitch_um(등방), shape_yx, axis_order=yx, origin_convention=top_left_cell_edge, valid mask. bbox는 half-open [xmin, ymin, xmax, ymax). layout/hotspot/valid의 frame·pitch·origin·shape가 모두 같아야 한다.
  • 32 지름 record: input_status = observed | missing | not_applicable. 관측 0 ≠ 누락 ≠ 높이 미만 vertical N/A. 보간·외삽·0 채움 없음.
  • vertical short: 실제 상부 layer(upper_actual_layer)에 귀속하고 height_um 근거가 있어야 한다. d < height_um만 N/A, 등호는 적용 대상. 5 µm 이상 높이는 없다는 사용자 사실은 유지하되 개별 높이를 추측하지 않는다.
  • 이진 이미지 극성: asset 참조의 value_semantics는 binary(nonzero가 표시, 기본) 또는 binary_zero_is_marked. 실제 hotspot PNG는 검정 배경 / 흰 패턴이므로 binary를 적는다(사용자 확인 2026-10-13). 자동 판별은 없고 non-synthetic asset은 반드시 명시한다.

6.2 real_hotspot_v1 (실제 폴더 import)

  • case 디렉터리 이름 불량명-전극1-layer1-전극2-layer2. 파일은 1.png, 2.png(전극), hotspot_<불량명><지름>.png, result/<불량명>.csv. case-local CSV가 없으면 다른 곳에서 대체하지 않는다.
  • hotspot은 전극 image보다 각 축 정확히 1000 px 작아야 하며 importer가 중앙 crop mask를 저장한다. frame origin (50, 50) µm, pitch 0.1 µm/px. 면적 = occupied pixel × 0.01 µm².
  • CSV defect_size(um),Area(um2)의 원문 문자열·정밀도를 보존하고, PNG 면적과의 일치 tolerance는 CSV 마지막 자릿수 절반 + 픽셀 면적 절반이다. 어느 쪽도 덮어쓰지 않는다.
  • product/design/source/process/exposure/unit, 전극 role/polarity, vertical height는 원천에 없으므로 null. 그래서 compare는 case별 원 면적만 내고 line/pixel·density·panel·delta는 unavailable, 지도는 blocked다. config의 condition_assignment와 pair 표를 확인된 값으로 넣어야 group 계산이 열린다.
  • 자원 제한: group 5억 cells, 전체 source 60억 cells, 보수적 전체 추정 8 GiB(max_operation_bytes로 낮출 수만 있음). 한 번에 한 PNG/crop mask만 materialize.

6.3 strict PNG reader

numeric mask PNG는 Pillow decode 전에 원본 byte buffer에서 signature, chunk 순서, 모든 CRC, IHDR, 단일 IDAT zlib stream과 inflated 길이, PLTE/index, scanline filter를 독립 검증한다. 전체 inflated stream을 쌓지 않고 bounded inflate block과 packed row 두 개만 유지한다.

수락조건
greyscale (colour type 0)bit depth 1/2/4/8. 모든 pixel 정확히 0/255 (8-bit L의 0/1도 수락). 0/1과 0/255 혼합은 거부
RGB · LA · RGBA8-bit, 모든 pixel이 정확히 검정/흰색, alpha 전부 255. luminance 변환·threshold 없음
palette (P)PLTE 존재, 사용 index 범위 안, 색은 정확히 검정/흰색, tRNS가 있으면 전부 255
interlacenone 또는 Adam7 (pass별 scanline 길이·filter 검증)

거부: 16-bit(png_unsupported_bit_depth), APNG, 투명도, 회색/유색 pixel, IEND 뒤 byte, orientation ≠ 1, 설치된 Pillow pixel limit(12.3.0 기본 89,478,485) 초과. 복구 방법은 "plain opaque black/white PNG로 다시 저장"이며 reader는 threshold·crop·회전·resize를 하지 않는다.

PNG 실패 사유 코드 전체

구조: png_invalid_signature, png_truncated_chunk, png_invalid_chunk, png_invalid_chunk_order, png_crc_mismatch, png_invalid_header, png_unknown_critical_chunk
데이터: png_invalid_idat_stream, png_idat_length_mismatch, png_invalid_scanline_filter, png_missing_palette, png_invalid_palette, png_palette_index_out_of_range
엄격성: png_apng_unsupported, png_invalid_transparency, png_nonopaque_transparency, png_nonopaque_pixels, png_unsupported_bit_depth, png_trailing_bytes, png_nonidentity_orientation, nonbinary_nominal_mask, unsupported_png_mode
decoder: png_pixel_limit_warning, png_pixel_limit_error, png_pixel_limit_disabled, png_decode_failed. hash 불일치: input_hash_mismatch.

6.4 review_roi_v1

  • 출처는 두 가지뿐: electrode_count_region(명시 threshold로 계산한 지도 영역 중 사용자가 고른 것)과 manual(기본). 검색 결과나 제품 간 대응으로 ROI를 자동 선택하지 않는다.
  • manual에는 product/design/frame/center_xy_um와 case 또는 명시 endpoint 문맥이 필요하다. 부족하면 blocked: case_context_required, 원본 shape 연결이 없으면 source_shape_required.
  • hotspot/CA/density/rate는 asset이나 tensor 입력으로 내보내지 않는다. 지도 대표 지름·threshold·4-neighbour는 선택 근거 provenance로만 남긴다. crop 크기(G4)는 crop_recipe: pending.
  • producer_commit은 패키지 자체가 git checkout 안에 있을 때만 HEAD를 기록하고, 아니면 null과 사유.

7핵심 계산 정의

7.1 line / pixel union과 transfer

union key는 (product, design, source/process 조건, exposure, analysis_layer, diameter, frame)다. 같은 layer라는 이유로 다른 노출·원천 조건을 합치지 않는다. 면적은 valid 안 셀 수 × pitch²다.

  • pair bucket: 한 class 안에서 서로 다른 pair membership 크기 1은 exclusive, 2 이상은 shared bucket. shared는 나누어 배분하지 않고 bucket ID별 한 번만 합산하며 exclusive + shared = class_total을 지름/layer/panel에서 검사한다.
  • 계보 vs 기여: pair_lineage_case_keys는 그 pair의 원천 전체(missing·관측 0 포함), contributing_source_case_keys는 해당 지름에서 실제로 bucket과 겹치는 case만.
  • 같은 pair의 여러 case를 OR한 뒤에도 원본 case별 CA·failure_type·layer·raw ID를 추적할 수 있어야 한다.

7.2 불량 유형 조각 (failure pieces, G7a)

같은 group의 mapped short case에서 lateral mask 합집합을 A, vertical 합집합을 B라 하면:

lateral_only = A \ B vertical_only = B \ A simultaneous = A ∩ B 세 조각은 서로 겹치지 않고 lateral_only + vertical_only + simultaneous = U
lateral_onlyvertical_onlysimultaneousinvalid / 미관측

line/pixel class와 무관하게 mapped short 전체를 쓰며 line/pixel·transfer·bucket에 더하거나 빼지 않는다. shared(다른 pair membership)와 simultaneous(다른 failure type)는 다른 개념이다. 높이 근거로 vertical이 모두 N/A인 지름은 vertical_only·simultaneous가 not_applicable이고 lateral_only와 전체 union은 lateral case로 계산한다. 위 색은 local_delta.html 썸네일의 조각 색과 같다.

7.4 density 가중·unit·panel (합성 계약에서만)

  • density는 지름마다 한 값(bin_semantics = per_bin, 2026-10-08). 연속 per-µm density가 아니므로 bin 폭을 곱하거나 적분하지 않으며 총합을 확률 1로 정규화하지 않는다.
  • per-bin 역면적 density(um^-2 등)가 확인된 때만 V = Σ area_um2 × density_per_um2. 실자료의 "10 count/glass"는 단위·조사면적 없이 쓸 수 없다(G1 pending).
  • unit_domain: 제품 간 µm/pixel은 같고(0.1 µm/px) pixel 수는 다르며 한 제품의 layer 크기는 같다. 2×2 → 한 unit 환산은 pending이라 divisor = null, 자동 /4 없음.
  • panel: 축별 floor | half_up_round로 unit 수 N을 Decimal로 구하고 V_panel = N × V_unit, delta = target − reference. N = 0이면 panel_has_no_units.
  • 같은 layer에 density 분포가 여럿이면 ambiguity 오류, 없으면 missing_layer_density_distribution로 그 layer만 null.

7.5 전극 수 지도 (electrode-map)

  • 대표 지름 기본 5 µm에서 각 셀을 덮는 short hotspot의 distinct electrode 수를 layer별로 센다. 제품 summary는 모든 layer의 pixelwise maximum이며 frame이 다르면 incompatible_layer_frames로 unavailable.
  • 기본 출력은 count 배열(NPZ)·discrete PNG·물리 extent sidecar뿐이다. 자동 threshold·영역·순위는 없고 --min-count k를 명시할 때만 4-neighbour 연결 성분을 영역으로 만든다(scipy 없이 자체 구현, electrode_map.py:32).
  • PNG는 count마다 한 방향으로 진해지는 discrete 색과 legend, invalid 회색과 count 0 흰색을 구별한다. 작은 격자는 max(1, ceil(400 / max(h, w))) 정수 배 nearest 확대, 2000 px 격자는 1:1. 2×2 domain을 그대로 표시하고 제품 간 overlay는 없다.
  • --per-cell-text는 4096 cells 이하에서만 셀별 텍스트를 추가한다.

7.6 fraction_of_frame (제품 수준, PLAN_v3 T3)

frame_area_um2 = shape_yx[0] × shape_yx[1] × pitch² (실자료는 중앙 2×2 crop frame) fraction_of_frame = area / frame_area_um2 (line, pixel_effective, transfer, union, 세 조각) delta_fraction = F_target − F_reference (같은 ComparisonKey·지름, 양쪽 available일 때만)

분자·분모가 같은 frame 위에 있으므로 G2의 /4가 상쇄되어 unit 크기가 다른 제품을 비교할 수 있다. 유한 2×2 경계 효과는 남는 한계이며 확률·수율·밀도 가중이 아니다. 한쪽에 없는 layer는 0이 아니라 *_layer_unknown. 기존 CSV 열은 유지하고 comparison_fractions.csv를 추가했다.

8.2 창 안 측정과 attributable core

  • 대상은 해당 제품·analysis_layer·지름 group의 mapped short union과 세 조각이며 창 안에서도 조각 합 = union을 검사한다. group은 정확히 하나여야 하고(no_source_group_* / ambiguous_source_group_*) design_version도 매칭에 포함된다.
  • 창 값: {value, partial_value, status, reasons, window_area_um2, valid_area_um2, fraction_of_window}. 완전성은 선언 십진수(Fraction) 경계로 판정해 frame 가장자리나 안쪽 invalid 셀에 맞닿은 창이 float 오차로 partial이 되지 않는다(리뷰 A2 반례 3000건 검증).
  • named_pair: endpoints가 있으면 unordered 전극 집합 + failure_type으로 case를 찾아 그 mask의 창 안 CA를 추가. group union을 넘으면 named_pair_exceeds_group_union_<side>로 unavailable(fail-closed).
  • jitter(--jitter-um j): 중심을 x·y 각각 ±j 이동한 네 창의 Δ_union 범위와 부호 일치를 기록. 임계값 없음.
  • explained_fraction: 모든 ready 쌍에 repeats_per_frame이 있을 때 side별 Σ(창 union CA × repeats) / frame_area와 참조 group의 fraction 차이를 나란히 둔다. 같은 group의 겹치는 창은 합집합으로 한 번 재고 repeats가 다르면 그 지름은 unavailable.
  • window_sensitivity_v1: 쌍×지름의 창 크기별 Δ_union, 부호 일치, 크기 쌍 간 |Δ| Spearman 순위 상관(정렬 지름), core 적용 가능 지름. 추천 창 크기는 계산하지 않으며 사용자가 G4를 정한다.

비용: 2000×2000 frame 합성에서 compute_areas 1.8 s(제품 2 × case 2 × 32 지름), 창 측정 쌍·창당 약 0.13 s. local_delta.json은 쌍·창당 약 0.4 MB라 --compact-json으로 행별 세부를 CSV에만 남길 수 있다. 실자료 비용은 case 수에 비례하는 compute_areas가 좌우한다.

단계하는 일검사
contextnumeric_v2와 원본 asset manifest를 다시 읽어 CA·line/pixel·지도와 ready ROI를 연결. 전극 수 배열을 numeric_map/*.npz로 저장상대 경로·SHA256 고정. blocked ROI는 join 후보에서 제외
sealnative DL1/DL2 결과의 정확한 SHA256, DL1 config fingerprint, DL2 index checkpoint_fingerprint·view_fingerprint, numeric context SHA256을 dl_file_exchange_v1 sidecar에 기록사용자 승인 checkpoint의 fingerprint를 입력해야 함. 다른 결과에서 복사하는 것은 승인이 아님
readhash·profile·fingerprint 검사 후 8-필드 복합 identity, frame, asset hash, 중심, endpoint binding을 정확히 맞춰 수치 옆에 DL 점수를 붙임불일치는 exit 2이고 기존 joined output도 지움. DL2 점수는 float64 cosine 6자리 재계산, 허용오차 1.5e-6
  • DL1은 제품 점수라 단일 case 문맥이 없다. 사용자가 확인한 dl1_bindings.json(product, input_identity, roi_id, source identity, frame, asset)이 없으면 dl1_product_source_context_required로 unavailable.
  • DL2 primary/supplementary는 별도 목록이며 supplementary를 primary로 재표시하지 않는다. unavailable은 primary 없음을 뜻한다.
  • DL1 입력 PNG(layout/electrode·CNT)는 검정 패턴 / 흰 배경, compare의 hotspot PNG는 흰 패턴 / 검정 배경이다. DL1 importer는 python -m psdl1.import_png → --inspect-grids → --export → --verify-bundle 순서로 manifest를 만든다.
  • DL2의 CNT/VIA view check는 global_contact_proxy_unverified 기하 proxy이며 실제 도통 검증이 아니다.
