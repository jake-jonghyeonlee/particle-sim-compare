이물(먼지 같은 작은 입자) 시뮬레이션 결과를 받아서 "어느 설계가 더 안전한가, 이 모양 변경이 불량을 얼마나 줄였나"를 숫자로 알려 주는 도구입니다. 이 문서는 그 도구가 무엇을 하고, 어떤 숫자를 내고, 지금 어디까지 왔는지를 그림과 쉬운 말로 설명합니다.

1한 줄로 말하면

시뮬레이터(particle-sim)는 "이물이 어디에 떨어지면 불량이 나는지"를 그림(흑백 이미지)으로 내줍니다. simcompare는 그 그림들을 받아서 넓이를 재고, 제품끼리 비교하고, 약한 자리를 지도로 그려 주는 계산기입니다. 새로 예측하는 AI 모델이 아니라, 이미 나온 결과를 정확하게 세는 도구입니다.

2왜 이런 도구가 필요한가

2.1 이물이 떨어지면 생기는 일

디스플레이 패널에는 아주 가는 전극(전기가 흐르는 선)이 촘촘히 깔려 있습니다. 공정 중에 지름 몇 µm짜리 이물이 두 전극 사이에 떨어지면 두 전극이 붙어 버립니다. 이것을 short라고 합니다. 이물이 크면 클수록 붙을 수 있는 자리가 넓어집니다.

2.2 시뮬레이터가 주는 그림: hotspot과 CA

시뮬레이터는 이물의 중심을 한 칸씩 옮겨 가며 "여기에 중심이 오면 short가 나는가"를 전부 확인하고, 불량이 나는 중심 자리를 흰색으로 칠한 흑백 그림을 내줍니다. 이 그림을 hotspot이라고 부릅니다. 흰색 칸의 넓이를 합친 값이 CA(critical area, 위험 넓이, 단위 µm²)입니다. 넓을수록 이물이 떨어졌을 때 불량이 될 확률이 큽니다.

2.3 설계자가 알고 싶은 두 가지

제품 전체로 보면, 어느 설계가 더 안전한가?
제품마다 화소 크기가 달라서 CA 숫자를 그냥 비교하면 큰 제품이 불리합니다. 그래서 "측정한 영역 넓이 대비 몇 %인가"로 바꿔 비교합니다. (→ 4.4)
이 자리 모양을 바꾸면, 불량이 얼마나 줄어드나?
비슷한 두 제품에서 설계자가 "여기와 여기가 같은 자리"라고 짝지어 주면, 그 둘레 같은 크기의 창 안에서 CA를 재고 차이를 냅니다. 눈으로 하기엔 너무 오래 걸리는 일입니다. (→ 4.5)

3자주 나오는 말 풀이

hotspot
이물 중심이 오면 불량이 나는 자리를 흰색으로 칠한 흑백 그림. 지름마다 한 장.
CA
hotspot의 흰 칸 넓이 합(µm²). 클수록 위험.
case
"어떤 불량 종류, 어떤 전극 둘, 어떤 층"의 한 조합. 폴더 이름이 불량명-전극1-층1-전극2-층2로 되어 있음.
frame
그림 한 장이 덮는 물리 영역. 왼쪽 위 좌표(µm), 칸 크기(0.1 µm), 칸 수로 정해짐. 실제 자료는 화소 2×2개 크기의 영역.
valid
그림에서 "관측한 칸"을 표시한 마스크. valid 밖은 "불량 없음"이 아니라 "안 봄"으로 취급.
line / pixel
전극 쌍을 두 묶음으로 나눈 분류. 선 불량(line)이 나는 쌍과 점(화소) 불량(pixel)이 나는 쌍. 분류표는 사용자가 줍니다.
lateral / vertical
옆으로 붙는 short(같은 층)와 위아래로 붙는 short(다른 층). 원천 case가 어느 쪽인지 적혀 있음.
전극 수 지도
각 칸마다 "서로 다른 전극 몇 개의 hotspot이 겹치는가"를 센 지도. 숫자가 큰 곳이 약한 자리.
ROI
검토할 위치. 사용자가 찍거나 지도에서 고른 자리. DL2에 "이 자리와 비슷한 구조를 찾아 달라"고 넘기는 단위.
DL1 / DL2
별도 저장소의 딥러닝 도구. DL1은 비슷한 제품을, DL2는 비슷한 위치를 찾습니다. 점수는 참고용이고 계산에는 안 들어갑니다.
gate (G1~G6)
사용자 답을 기다리는 질문 번호. 답이 없으면 그에 걸린 계산은 비워 둡니다.

4이 도구가 내는 다섯 가지 숫자

다섯 숫자는 서로 다른 질문에 답하는 것이라 하나로 합치지 않습니다. 각각 따로 봅니다.

4.1 line / pixel 넓이

같은 층의 short case들을 전극 쌍 분류표에 따라 line 묶음과 pixel 묶음으로 나누고, 각 묶음의 hotspot을 포개서(합집합) 넓이를 잽니다. 한 칸이 두 묶음 모두에 들어가면 line을 우선으로 셉니다. 겹친 부분은 "transfer"라는 이름으로 따로 기록만 합니다.

같은 묶음 안에서도 "어느 전극 쌍 때문인가"를 남깁니다. 한 쌍만 관여한 칸은 exclusive, 여러 쌍이 겹친 칸은 shared로 묶어 두고 shared는 한 번만 더합니다. 그래서 나중에 "이 넓이는 어느 쌍에서 왔나"를 거슬러 찾을 수 있습니다.

4.2 불량 종류별 조각 (옆 short / 위아래 short / 둘 다)

같은 층의 short case를 이번에는 종류로 나눕니다. 옆으로 붙는 lateral short만 나는 칸, 위아래로 붙는 vertical short만 나는 칸, 둘 다 나는 칸. 세 조각은 겹치지 않고 합치면 전체 short 넓이가 됩니다.

4.3 전극 수 지도

한 제품의 그림을 모두 포개 놓고, 칸마다 "서로 다른 전극 몇 개가 여기서 short를 낼 수 있나"를 셉니다. 숫자가 큰 칸은 여러 전극이 몰려 있어 약한 자리입니다. 기본 지름은 5 µm이며 층별 지도와, 모든 층 중 최댓값을 모은 제품 지도를 만듭니다.

4.4 영역 넓이 대비 비율 (제품끼리 비교할 때)

제품 A는 화소가 크고 제품 B는 작다면, 같은 넓이의 그림 안에 B의 구조가 더 많이 들어갑니다. CA 숫자만 비교하면 공정하지 않습니다. 그래서 CA ÷ 측정 영역 넓이, 즉 "영역의 몇 %가 위험한가"로 바꿔 비교합니다. 단위가 없는 비율이라 화소 크기가 달라도 나란히 놓을 수 있습니다.

4.5 같은 자리의 창 안 비교 (국부 ΔCA)

설계자가 "제품 A의 이 자리와 제품 B의 저 자리는 같은 구조"라고 짝을 지어 주면, 두 자리 둘레에 같은 크기의 정사각형 창(예: 한 변 20 µm)을 놓고 그 안의 CA를 각각 잽니다. 그 차이(B − A)가 "모양 변경이 불량을 얼마나 바꿨나"입니다. 창 크기가 같으니 화소 크기가 달라도 바로 비교할 수 있습니다.

몇 가지 세부 규칙이 있습니다.

  • 창 크기는 사용자가 정합니다. 코드에 기본값이 없습니다. 10 / 20 / 30 µm 세 가지로 돌려 보고 어느 크기가 안정적인지 표(민감도 표)를 보고 고릅니다.
  • 창 안쪽 핵심 구역: 창 가장자리의 불량은 창 밖 전극 때문일 수도 있습니다. 그래서 창에서 이물 지름만큼 안쪽으로 들어간 작은 정사각형 값도 따로 냅니다. 창이 지름보다 작으면 이 값은 "해당 없음"입니다.
  • 창이 그림 밖으로 나가거나 안 본 칸을 포함하면 그 쪽 값은 "부분"이 되고 차이는 비웁니다. 반쪽짜리 차이를 만들지 않습니다.
  • 흔들어 보기: 라벨을 찍을 때 조금 어긋날 수 있으니, 중심을 ±0.5 µm 정도 네 방향으로 옮겨 다시 재서 결과 부호가 바뀌는지 기록합니다.
  • 결과는 쌍마다 A/B 그림 조각과 숫자 표를 나란히 둔 HTML로도 나옵니다. 폐쇄망에서 파일만 열면 됩니다.

5결과를 읽는 법

모든 숫자에는 상태가 붙어 있습니다. 숫자만 보지 말고 상태를 먼저 보세요. 비어 있는 칸은 "0"이 아니라 "아직 모름"입니다.

available
다 봤고, 쓸 수 있는 값. "0"도 여기 들어갑니다(봤는데 불량 자리가 없음).
partial
일부만 봄. 값 칸은 비우고 "본 부분까지의 합"을 따로 적습니다. 이유가 같이 붙습니다.
unavailable
계산할 수 없음. 사용자 답을 기다리는 질문이 걸려 있거나 입력이 안 맞음. 이유를 적습니다.
not_applicable
원래 해당 없음. 예: 층 간격보다 작은 이물의 위아래 short.

명령을 실행하면 끝날 때 숫자 하나(종료 코드)를 돌려줍니다.

종료 코드뜻할 일
0요청한 결과가 모두 나옴결과 파일을 봅니다
3일부는 나왔고 일부는 비어 있음비어 있는 항목의 이유(reasons)를 확인합니다. 대개 사용자 입력이 더 필요합니다

실제 자료를 처음 넣으면 3이 나오는 것이 정상입니다. 원천 폴더에는 제품·공정·전극 쌍 분류표 같은 정보가 없어서, 사용자가 설정 파일에 확인된 값을 넣어 주기 전까지는 "그림 넓이"만 계산하고 나머지는 비워 둡니다.

6실제로 어떻게 쓰나

폐쇄망 Windows PC에서 명령 프롬프트(CMD)로 씁니다. 설치 파일(wheel 묶음)은 Git에 들어 있고 설치·도움말 실행은 사용자가 성공을 확인했습니다.

자주 쓰는 명령은 이렇습니다. 경로는 실제 위치로 바꿉니다.

:: 실제 자료 가져오기 (출력 폴더는 새 폴더)
.venv-cmd\Scripts\python.exe -m simcompare import-hotspots --root "D:\data\input\hotspot" --out "D:\data\imported\reference"

:: 점검 → 비교 → 지도
.venv-cmd\Scripts\python.exe -m simcompare validate-data --config "D:\data\real.yaml"
.venv-cmd\Scripts\python.exe -m simcompare compare       --config "D:\data\real.yaml"
.venv-cmd\Scripts\python.exe -m simcompare electrode-map --config "D:\data\real.yaml"

:: 같은 자리 창 비교 (창 크기는 반드시 적어 줌)
.venv-cmd\Scripts\python.exe -m simcompare compare-windows --config "D:\data\real.yaml" ^
    --correspondence "D:\data\pairs.json" --window-sizes 10 20 30 --sort-diameter-um 5 --out "D:\data\local"

연습용 가짜 자료가 필요하면 demo-data --out demo_data로 만들 수 있습니다. 가짜 자료는 코드가 도는지 보는 용도이지 실제 결과가 아닙니다.

7세 개의 저장소

이 일은 저장소 세 개가 나눠 맡습니다. 이 문서의 주인공은 C입니다.

8이 도구가 지키는 약속

  1. 그림을 고치지 않습니다. 늘리기, 줄이기, 회전, 흐리기 없이 원본 칸을 그대로 셉니다. 두 제품 그림을 겹쳐 맞추지도 않습니다.
  2. 모르는 건 모른다고 합니다. 사용자가 아직 답하지 않은 값(밀도 단위, 화소 하나로 환산하는 방법, 창 크기)은 코드에 기본값으로 넣지 않습니다. 그 값이 필요한 계산은 비우고 이유를 적습니다.
  3. 비어 있음과 0을 구분합니다. "봤는데 없음"은 0, "안 봄"은 빈칸, "원래 해당 없음"은 따로 표시합니다. CSV에서도 빈칸을 0으로 바꾸지 않습니다.
  4. 이름을 바꾸지 않습니다. 전극 이름, case 이름을 대소문자나 기호까지 그대로 둡니다. 나중에 원천 파일로 되돌아갈 수 있어야 하기 때문입니다.
  5. DL은 조수입니다. DL1·DL2 점수는 결과 옆에 표시만 하고 어떤 숫자에도 곱하거나 더하지 않습니다.
  6. 입력 파일을 의심합니다. PNG는 열기 전에 손상·투명도·16비트·회전 정보까지 검사하고, 조금이라도 애매하면 "다시 저장해 달라"고 거부합니다. 모든 입력 파일의 해시(지문)를 기록합니다.

9지금까지 어떻게 왔나

한 달 남짓 동안 한 번 큰 방향 전환이 있었습니다. 처음에는 여러 입력을 섞어 배우는 딥러닝 모델로 "비슷한 사례 찾기"를 하려 했지만, 10월 7일에 "이미 나온 그림을 정확히 세는 계산기"로 다시 만들었습니다. 그 뒤로는 사용자 답변을 받을 때마다 계산 범위를 한 단계씩 넓혀 왔습니다.

  • 9/16첫 설계. 다섯 가지 입력을 섞어 배우는 딥러닝 모델 (지금은 보관용 브랜치에만 남음)
  • 9/27CA 단위 버그 수정. 시뮬레이터가 이미 나눈 값을 또 나누던 문제
  • 10/7방향 전환. 계획서 v2 채택: 그림 세기 계산기 + 전극 수 지도 + DL 분리
  • 10/8~9핵심 계산 구현과 독립 리뷰 두 차례. 옛 기능(학습·검색) 정리. DL1·DL2 저장소 시작. 폐쇄망 인수 절차
  • 10/13실제 파일 형식 확정(검정 배경 흰 패턴, 칸 0.1 µm). PNG 엄격 검사기
  • 10/15실제 폴더 가져오기 명령, Windows 오프라인 설치 묶음
  • 10/18같은 자리 창 비교(compare-windows), 비율 비교, 창 크기 민감도, 나란히 보는 HTML. 독립 리뷰 2회 통과

10지금 상태와 남은 일

사용자 답을 기다리는 것 (답이 올 때까지 해당 계산은 빈칸)

  • G1 이물 밀도의 단위와 조사 면적. 지름마다 값 하나라는 것까지는 확정
  • G2 화소 2×2 그림에서 화소 하나 값을 어떻게 뽑을지. 칸 크기 0.1 µm는 확정
  • G4 창 크기. 10 / 20 / 30 µm로 실험해 보고 고르기로 함
  • G5·G6 DL1의 실제 격자 크기, 정답 라벨과 합격 기준

실제 자료로 해 봐야 하는 것

  • 폐쇄망에서 실제 그림 수백 장으로 비교·지도 실행 (메모리 16 GB 확인 포함)
  • 설계자가 짝지은 수십 개 자리의 창 비교 표를 보고 "눈으로 본 판단과 맞다"고 기록
  • 창 크기 세 가지 중 하나 고르기 (G4 닫기)
  • DL2가 찾은 자리와 단순한 기준선(패턴 매칭) 중 어느 쪽이 더 맞는지 비교

일부러 미뤄 둔 것

  • 수율(%)로 환산하기
  • 여러 층 윤곽을 한 화면에 겹쳐 보는 화면, 클릭해서 따라가는 뷰어
  • 설계 변경 하나하나에 불량을 배분하는 분석

11코드는 어떻게 생겼나

Python 패키지 하나(src/simcompare, 26개 파일, 약 9,700줄)와 시험(37개 파일, 약 7,700줄)으로 되어 있습니다. 외부 라이브러리는 numpy, pandas, pillow 정도이고 딥러닝 라이브러리는 없습니다.

묶음파일하는 일 (쉬운 말)

자료 모양numeric_schema.pyframe, case, 전극 쌍 같은 자료의 모양과 검사 규칙
세기measurement.py, linepixel.py, density.py흰 칸 세기, line/pixel·종류별 조각·비율, (가짜 자료에서만) 밀도 곱하기
지도electrode_map.py, heatmap.py전극 수 지도 계산과 PNG 그리기
같은 자리 비교correspondence.py, local_delta.py, local_delta_report.py대응 위치 파일 읽기·변환, 창 안 비교, 나란히 보는 HTML
DL과 주고받기roi_export.py, dl_results.py검토 위치 내보내기, DL 결과 파일의 지문 고정과 검사
